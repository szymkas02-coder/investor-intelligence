This document addresses two problems with the current LightGBM regime classifier
and maps out concrete improvement routes in priority order.

---

## The Two Core Problems

### 1. Label Circularity

The current classifier is trained on **rule-based labels** generated by
`processing/labels.py`. Those rules use `vix_close`, `spread_10y_3m`,
`acwi_ret_63d`, and `cpi_us_yoy` as thresholds. The classifier then receives
those same variables as features and learns to reproduce the thresholds.

**Consequence:** The model is not discovering market regimes — it is
approximating a lookup table. The 100% in-sample label agreement confirms
this. The CV macro-F1 of 0.43 reflects the model's inability to generalize
the rule to unseen time periods, not its ability to detect regimes.

### 2. Too Few Regime Episodes

With ~1,600 labeled rows (2010–2026) and 4 imbalanced classes, there are
roughly 8–12 distinct regime episodes in the training data. LightGBM is a
high-capacity model designed for thousands of IID samples. Applying it here
is using a sledgehammer on a nail — the model overfits to the few transitions
it has seen.

## Improvement Route 1 — NBER Recession Labels (Quick Win)

**What:** The National Bureau of Economic Research (NBER) publishes official
US recession dates back to 1854, freely available at
`https://www.nber.org/research/data/us-business-cycle-expansions-and-contractions`.
Fred also serves them as the series `USREC` (monthly binary flag).

**Why this fixes circularity:** NBER dates are determined by a committee of
economists using a broad set of indicators — GDP, employment, income,
industrial production. They are explicitly NOT derived from VIX or yield
curves. They are external ground truth, not a rule applied to your features.

**What you get:** A binary `recession / expansion` label going back to 2010
(or further). This is a simpler problem than 4-class regime detection, but
it is a *real* ML problem — the model is no longer learning its own rules.

**Implementation:**
```python
# ingestion/fred.py already fetches FRED series — add:
series_ids = [..., "USREC"]   # monthly 0/1 recession indicator
```
Then use `USREC` as a binary target alongside (or instead of) the rule-based
regime label. A model predicting NBER recessions from VIX + yield curve +
macro features is a legitimate classifier.

**Limitation:** Binary only (recession vs expansion). Stagflation and
deflation distinctions require additional labels.

**Key reference:** NBER Business Cycle Dating Committee methodology,
Hall et al. (2003), *"The NBER's Recession Dating Procedure"*.

## Improvement Route 2 — Hidden Markov Model on Shiller Data (Best Fix)

**What:** A Hidden Markov Model (HMM) learns latent regime states directly
from observed data without any human-defined labels. The EM algorithm finds
the state sequence that best explains the observations.

**Why this fixes both problems:**
- No labels → no circularity
- Shiller data goes back to 1871 → ~1,800 monthly observations → enough
  episodes for the EM algorithm to converge reliably
- The model discovers regimes from price dynamics, not from your threshold rules

**Recommended library:** `hmmlearn` (GaussianHMM or GMMHMM)

**Features to use from `shiller.csv`:**
```
- Monthly log return of SP500 (from SP500 column)
- CPI YoY change (from Consumer Price Index column)
- Long Interest Rate (10Y bond yield proxy)
- Earnings yield (Earnings / SP500)
- CAPE (PE10) — Shiller's cyclically-adjusted P/E
- Dividend yield (Dividend / SP500)
```

**Number of states:** Literature recommends 2–4 for financial data.
- 2 states: bull / bear (Hamilton 1989 — the original paper)
- 3 states: bull / bear / high-volatility (Ang & Timmermann 2012)
- 4 states: maps to risk_on / risk_off / stagflation / deflation

Use BIC (Bayesian Information Criterion) to select the number of states.

**Key pitfall — EM look-ahead:** The standard EM algorithm for HMM uses the
full sequence (forward-backward algorithm), which technically uses future
observations to estimate past states. For backtesting this is look-ahead bias.

**Mitigation:** Use an **online / filtering-only** HMM (forward pass only,
no backward smoothing) for regime assignment during the test period. Fit the
model on a fixed training window (e.g. 1871–1999), then use only the forward
filter for 2000+.

**Key references:**
- Hamilton, J.D. (1989). *"A New Approach to the Economic Analysis of
  Nonstationary Time Series and the Business Cycle."* Econometrica, 57(2).
  → The foundational paper. 2-state Markov switching model on US GNP.
- Ang, A. & Timmermann, A. (2012). *"Regime Changes and Financial Markets."*
  Annual Review of Financial Economics, 4.
  → Comprehensive survey of regime models in finance. Covers HMM, GMM,
    threshold models. Highly recommended read.
- Guidolin, M. & Timmermann, A. (2007). *"Asset Allocation under Multivariate
  Regime Switching."* Journal of Economic Dynamics and Control.
  → Directly relevant: regime-conditional asset allocation.

**Implementation sketch:**
```python
from hmmlearn.hmm import GaussianHMM
import numpy as np

# Monthly features from shiller.csv
X = df[["sp500_ret", "cpi_yoy", "long_rate", "earnings_yield"]].dropna().values

# Fit on pre-2000 data only
train = X[df["date"] < "2000-01-01"]
model = GaussianHMM(n_components=4, covariance_type="full",
                    n_iter=1000, random_state=42)
model.fit(train)

# Forward-filter only for test period (no look-ahead)
test = X[df["date"] >= "2000-01-01"]
regimes = model.predict(test)   # Viterbi decode — acceptable for monthly
```

## Improvement Route 3 — CAPE Valuation Signal (Different Question)

**What:** Rather than classifying the current regime, build a separate model
that predicts **long-horizon forward returns** from the Shiller CAPE ratio.

**Why it's different:** This doesn't answer "what regime are we in today?"
It answers "given today's valuation, what is the expected 10-year real return?"
These are complementary signals — the regime classifier is tactical (months),
the CAPE signal is strategic (years).

**Empirical finding (Campbell & Shiller 1988, 1998):** CAPE explains ~40% of
the variance in 10-year forward real returns in US data since 1871.
At CAPE > 30 (current ~33), historical median 10Y real return is ~2%.
At CAPE < 15, historical median 10Y real return is ~10%.

**Implementation:** Simple regression or quantile regression:
```
target  = SP500 real return over next 10 years (known in training data)
features = CAPE, real long rate, CPI trend
model   = QuantileRegressor (sklearn) for 25th / 50th / 75th percentile
```

This is robust to overfitting because it is a near-linear relationship with
strong economic theory behind it. No walk-forward CV drama.

**Key references:**
- Campbell, J.Y. & Shiller, R.J. (1988). *"Stock Prices, Earnings, and
  Expected Dividends."* Journal of Finance.
- Campbell, J.Y. & Shiller, R.J. (1998). *"Valuation Ratios and the
  Long-Run Stock Market Outlook."* Journal of Portfolio Management.
- Asness, C. (2012). *"An Old Friend: The Stock Market's Shiller P/E."*
  AQR Capital white paper. (Freely available on AQR website)

## Improvement Route 4 — Ensemble (Final Form)

Once routes 1–3 are built, the regime signal fed into the decision engine
becomes a weighted blend:

```
regime_prob_risk_off =
    0.35 × hmm_prob_risk_off          # unsupervised, 155Y of data
  + 0.35 × lgbm_prob_risk_off         # supervised, current features
  + 0.20 × nber_recession_prob        # external ground truth
  + 0.10 × cape_valuation_flag        # long-horizon context
```

Weights should be determined by out-of-sample log-loss on a held-out period
(e.g. 2015–2020) rather than hand-tuned.

**Why ensemble:** The three base models have genuinely different failure modes.
LightGBM fails on unseen macro regimes. HMM fails on structural breaks
(Great Depression dynamics may not recur). NBER labels lag the actual
recession by months. Blending reduces the impact of any single model's blind
spot.
