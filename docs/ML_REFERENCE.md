## 1. HMM Regime Detector

**File:** `ml/hmm_regime.py`  
**Artifact:** `models/hmm_regime.pkl`  
**DB table:** `hmm_predictions`  
**Retrain:** `python ml/hmm_regime.py train`

### Purpose

Classifies the current market into one of four qualitative regimes without any
pre-labelled training data. This is the primary regime signal used by the decision
engine and the dashboard.

### Inputs

| Feature | Source | Description |
|---------|--------|-------------|
| `sp500_log_ret` | `shiller.csv` | Monthly log return of S&P 500 |
| `vol_12m` | `shiller.csv` | 12-month rolling std of log returns |
| `cape` | `shiller.csv` | Cyclically Adjusted P/E (PE10) |
| `excess_cape_yield` | derived | `1/CAPE − real_long_rate` (equity vs bond premium) |
| `cpi_mom` | `shiller.csv` | Month-on-month CPI change |
| `long_rate` | `shiller.csv` | 10-year US nominal yield |

Training data: Shiller monthly CSV, 1871–present (~1,745 rows).  
Training window: **full dataset** — all 155 years used for fitting. The pre-2000
cutoff was removed (2026-05-22): more historical episodes give better transition
matrix estimates. Look-ahead is prevented by using the **Viterbi forward filter**
(not backward smoothing) for state assignment.

### Method

**Gaussian Hidden Markov Model** (hmmlearn `GaussianHMM`, full covariance matrix).

A HMM assumes the data is generated by a hidden discrete state that follows a
first-order Markov chain. Each state has a Gaussian emission distribution over the
feature vector. The model learns:
- The **transition matrix** A (probability of moving from state i to state j each month)
- The **emission parameters** μ_i and Σ_i per state
- The **initial state distribution** π

Training uses the Baum-Welch algorithm (expectation-maximisation on sequences).
Prediction uses the Viterbi algorithm (most probable state sequence given observations)
for the state label, and forward-algorithm probabilities for the per-state confidence.

**Model selection:** BIC is computed for n_states ∈ {2, 3, 4}. The current optimal
is n=4 (confirmed by BIC). States are labelled post-hoc by mean return rank:
- State with highest mean log return → **bull**
- State with second highest → **consolidation**
- State with low mean return + compressed equity premium (negative excess CAPE yield) + elevated vol → **stagflation** (displayed as "Expensive market" in UI)
- State with most negative mean return → **bear**

### Output

`hmm_predictions` row per month:

| Column | Type | Description |
|--------|------|-------------|
| `date` | DATE | Month |
| `state_label` | TEXT | `bull / consolidation / stagflation / bear` |
| `prob_bull` | FLOAT | Probability of bull state |
| `prob_bear` | FLOAT | Probability of bear state |
| `prob_consolidation` | FLOAT | Probability of consolidation state |
| `model_version` | TEXT | `hmm_4state_YYYY-MM-DD` |

`backend/hmm_utils.py::resolve_hmm_probs()` handles the stagflation state specially:
when the model assigns `state_label = stagflation`, the stored probabilities are
near-zero due to numerical underflow (the Gaussian likelihood of CAPE=39 is
essentially zero under a centroid of CAPE~20). The resolver sets `p_stagflation=0.99`
and redistributes.

### Known Limitations

- **CAPE=39 is outside the training distribution.** The stagflation cluster centroid
  has CAPE~20. The model assigns this state because it is the nearest cluster, but
  with very high uncertainty. The true current CAPE has no close historical analogue
  in the training data.
- **Monthly resolution.** The model uses monthly Shiller data. Daily predictions
  are just the last available monthly value forward-filled — there is no intra-month
  updating.
- **Gaussian emissions.** Tail events (2008, 2020) are underweighted because Gaussian
  distributions underestimate fat tails. Student-t emissions would be more appropriate
  but are not implemented.
- **Label instability.** Re-running BIC on different subsets sometimes selects 3 states
  instead of 4, which collapses `stagflation` and `consolidation` into one cluster.
  The 4-state model is manually preferred and saved.

## 2. Kaplan-Meier Regime Duration

**File:** `ml/regime_duration.py`  
**Artifact:** none (computed from DB, no pkl)  
**DB table:** `regime_duration_stats`  
**Retrain:** `python ml/regime_duration.py compute`

### Purpose

Answers: *given that the market has been in regime X for T months, how unusual is
that, and what is the probability it is still ongoing?* This contextualises the HMM
regime on the dashboard — the KM survival curve tells the user whether the current
episode is young, median, or far into the tail of historical durations.

### Inputs

The full history of `hmm_predictions.state_label` (monthly, ~1,745 rows back to 1880).
Each contiguous run of the same state constitutes one **episode**. Episodes are
extracted as:
- `start_date`, `end_date`, `duration_months`
- `observed = True` if the episode ended (transitioned to a different state),
  `observed = False` if it is the current ongoing episode (censored in KM terminology)

### Method

**Kaplan-Meier survival estimator** — the standard non-parametric method for
estimating survival functions from censored data, identical to its use in medical
clinical trials.

The survival function S(t) = P(episode duration > t) is estimated as:

```
S(t) = ∏_{t_i ≤ t} (1 − d_i / n_i)
```

where at each observed event time t_i, d_i episodes ended and n_i were still ongoing
(at risk). Censored observations (the current episode) contribute to the "at risk"
count up to their last known time but are not counted as events.

95% confidence intervals use Greenwood's formula.

This is mathematically identical to radioactive decay half-life estimation, or to
the statistical treatment of storm lifetime distributions in atmospheric science —
the physics analogy intentionally used in the UI tooltip.

Per-regime estimates are stored in `regime_duration_stats`:
- `km_survival` at each observed transition time
- `km_survival_lower / upper` (95% CI)
- `n_at_risk`, `n_events`

The dashboard queries the row where `duration_months <= current_duration` and picks
the last one, giving the survival probability at the current episode length.

### Output

`regime_duration_stats` — one row per (regime, duration_months) combination.

Dashboard also shows: median duration (t where S(t) ≤ 0.50), P25, P75.

### Known Limitations

- **Sample sizes are small.** ~145 years of monthly data gives perhaps 30–50 episodes
  per state. KM confidence intervals are wide, especially at long durations.
- **The current stagflation episode (73 months) is far beyond any historical precedent**
  (P75 = 73 months, meaning we are at the very edge of the observed distribution).
  KM survival at 73 months = 0.20, but the CI is [0.03, 0.48] — wide.
- **HMM label instability** (see Section 1) affects episode boundaries. A retraining
  that produces a 3-state model would break the KM estimates for `stagflation`.

## 3. Random Forest Volatility Forecaster

**File:** `ml/volatility.py`  
**Artifacts:** `models/vol_rf_21d_YYYY-MM-DD.pkl`, `models/vol_rf_63d_YYYY-MM-DD.pkl`  
**DB table:** `volatility_forecasts`  
**Retrain:** `python ml/volatility.py train`

### Purpose

Forecasts annualised realised volatility of VWCE.DE (using ACWI as a proxy with
longer history) at two horizons: 21 trading days (~1 month) and 63 trading days
(~1 quarter). Used by the decision engine to apply a volatility overlay (high vol
→ prefer DCA over lump sum).

### Inputs

**HAR-RV features** (Corsi 2009 — the academic benchmark for vol forecasting):

| Feature | Construction | Rationale |
|---------|-------------|-----------|
| `vol_21d` | `acwi_vol_21d` from daily_features | Monthly realised vol lag (the dominant predictor) |
| `vol_5d_approx` | `vol_21d × √(5/21)` | Weekly lag approximation |
| `vol_1d_proxy` | `|acwi_ret_1d| × √252` | Daily lag proxy |
| `vol_63d` | `acwi_vol_63d` from daily_features | Quarterly lag — captures long memory |

**Macro features** (add regime context that pure HAR-RV misses):

| Feature | Rationale |
|---------|-----------|
| `vix_close` | Implied vol — most correlated with near-term realised vol |
| `vix_change_5d` | VIX momentum |
| `spread_10y_3m` | Yield curve inversion precedes vol regime shifts |
| `acwi_ret_5d`, `acwi_ret_21d` | Sharp drops → vol clustering (leverage effect) |
| `usdpln_vol_21d` | PLN vol proxies global risk-off sentiment |
| `cpi_us_yoy`, `fed_funds_rate` | Macro regime context |

**Target:** forward annualised realised vol = `std(log_returns over next N days) × √252`

### Method

**Random Forest Regressor** (sklearn, 200 trees, `min_samples_leaf=5`).

The RF extends the linear HAR-RV model by capturing non-linear interactions: for
example, the monthly vol lag may be more predictive during yield-curve inversions
than in normal regimes. A linear model cannot represent this without explicit
interaction terms.

**Walk-forward cross-validation** (5 splits, `TimeSeriesSplit`) — random CV is
invalid for time series because it causes look-ahead leakage.

**Confidence interval:** For each prediction, the 10th and 90th percentile of
leaf-node predictions across all trees is used. This exploits the diversity of
the forest's individual trees to produce an honest interval without assuming
a parametric distribution.

**Benchmark:** GARCH(1,1) was tested using a 2-year rolling walk-forward (152
windows × 21d). Result: RF RMSE=0.0512, GARCH RMSE=0.0558. RF beats GARCH by
8.2%, confirming that macro context features add predictive power beyond
pure GARCH dynamics.

### Output

`volatility_forecasts` — one row per (date, horizon):

| Column | Description |
|--------|-------------|
| `vol_forecast` | Point forecast (annualised, decimal: 0.15 = 15%) |
| `vol_lower` | 10th percentile |
| `vol_upper` | 90th percentile |
| `horizon_days` | 21 or 63 |

### Known Limitations

- **VWCE.DE history starts 2019.** The model uses ISAC.L (iShares ACWI) as proxy,
  which has data from 2011. Still only ~15 years of daily returns — limited for
  capturing rare high-vol regimes.
- **Target is realised vol, not implied vol.** The model forecasts what volatility
  you will actually experience, not what the market prices in. In calm periods, the
  forecast can be optimistically low if an unforeseeable shock occurs.
- **Heteroscedasticity.** The RF does not model the variance of variance (VVIX).
  Adding VVIX as a feature is a potential improvement.

## 4. LightGBM FX Quantile Forecaster

**File:** `ml/currency.py`  
**Artifacts:** `models/fx_lgbm_USDPLN_{horizon}d_q{quantile}_YYYY-MM-DD.pkl` (6 files)  
**DB table:** `fx_forecasts`  
**Retrain:** `python ml/currency.py train`

### Purpose

Forecasts the USD/PLN exchange rate at two horizons (21d, 63d) in three scenarios:
pessimistic (90th percentile = PLN weakest), median, and optimistic (10th percentile =
PLN strongest). Used on the dashboard fan chart to show the range of exchange rate
uncertainty, which is relevant because VWCE.DE is EUR-denominated and the investor
is PLN-based.

**Important framing:** This model is intentionally presented as an **uncertainty tool**,
not a directional forecast. The Meese-Rogoff result (1983) — replicated many times —
shows that no model consistently beats a random walk for forecasting FX direction.
The median forecast is near-random; the *width of the band* (90th minus 10th
percentile) is the useful output.

### Inputs

| Feature | Rationale |
|---------|-----------|
| `rate_differential` | `fed_funds_rate − nbp_rate`: interest rate parity (UIP theory) |
| `cpi_differential` | `cpi_us_yoy − cpi_pl_yoy`: purchasing power parity (PPP theory) |
| `usdpln_ret_21d` | Recent FX momentum |
| `vix_close` | PLN is a high-beta EM currency — depreciates sharply in risk-off |
| `acwi_ret_21d` | Global equity momentum as risk proxy |
| `spread_10y_3m` | Yield curve signals capital flow direction |
| `hy_spread` | Credit stress → PLN outflows |

Note: `usdpln` (the raw level) is **intentionally excluded** — using the current
level as a feature would make the model trivially predict "rate barely moves" with
artificially low error. Returns and differentials are the economic signals.

### Method

**LightGBM with `objective='quantile'` and `alpha=q`** — optimises the pinball
(quantile) loss directly:

```
L(y, ŷ) = q × max(y−ŷ, 0) + (1−q) × max(ŷ−y, 0)
```

Three separate models per horizon (q=0.10, 0.50, 0.90). Walk-forward CV with a
21-day gap between train and validation window (equal to the shorter forecast horizon)
to prevent autocorrelation leakage.

**Quantile crossing prevention:** the q=0.10 forecast is clipped to not exceed q=0.50,
and q=0.90 is clipped to not go below q=0.50, at prediction time.

### Output

`fx_forecasts` — three rows per date per horizon (one per quantile):

| Column | Description |
|--------|-------------|
| `pair` | `USDPLN` |
| `horizon_days` | 21 or 63 |
| `rate_point` | Median forecast (PLN per 1 USD) |
| `rate_lower` | 10th percentile (PLN strongest) |
| `rate_upper` | 90th percentile (PLN weakest) |

### Known Limitations

- **Direction near-random** at 21d+ (Meese-Rogoff). The median is not actionable as a
  trade signal. The band width is useful.
- **PLN-specific model.** Any structural change in Polish monetary policy (e.g. NBP
  joining euro zone) would invalidate the rate differential features.
- **No macro surprise features.** NFP releases, FOMC surprises, geopolitical shocks
  are not captured. These cause the largest single-day FX moves.

## 5. LightGBM Recession Classifier

**File:** `ml/recession.py`  
**Artifact:** `models/recession.pkl`  
**DB table:** `recession_predictions`  
**Retrain:** `python ml/recession.py train`

### Purpose

Estimates the probability that the US economy is currently in recession. Used as a
secondary signal in the decision engine — high recession probability combined with
bearish HMM state triggers a WAIT recommendation.

### Inputs

**Original 8 features (Estrella-Mishkin, 1998):**

| Feature | Lead time | Rationale |
|---------|-----------|-----------|
| `spread_10y_3m` | 8–12 months | Yield curve inversion — best single predictor (Estrella-Mishkin) |
| `spread_10y_2y` | 6–10 months | Complementary inversion signal |
| `vix_close` | 1–6 months | Fear gauge |
| `acwi_ret_63d` | 1–3 months | 3-month equity momentum — markets lead GDP |
| `unemployment_us` | coincident | Sahm rule basis |
| `fed_funds_rate` | varies | Monetary tightening |
| `cpi_us_yoy` | varies | Inflation pressure |
| `usdpln_vol_21d` | 1–3 months | Global risk-off proxy |

**4 new real-time leading indicators (added 2026-05-16):**

| Feature | Series | Rationale |
|---------|--------|-----------|
| `sahm_indicator` | FRED SAHMREALTIME | Real-time Sahm rule — triggers at 0.50 |
| `initial_claims` | FRED ICSA | Weekly jobless claims — 4–6 week lead |
| `housing_permits` | FRED PERMIT | Conference Board LEI component |
| `indpro` | FRED INDPRO (YoY%) | Industrial production — LEI component |

**Ground truth:** `USREC` from FRED (NBER binary recession indicator, monthly).
Forward-filled to daily.

### Method

**LightGBM classifier** with class-imbalance weighting (`scale_pos_weight = n_neg/n_pos`).
**Isotonic calibration** (Platt scaling variant) applied via `CalibratedClassifierCV`
to convert raw scores to well-calibrated probabilities.

Walk-forward cross-validation: sliding 20-year windows, step 3 years.

### Output

`recession_predictions` — daily probabilities:

| Column | Description |
|--------|-------------|
| `recession_prob` | Calibrated probability of US recession (0–1) |
| `recession_pred` | Binary threshold at 0.50 |

### Known Limitations

- **NBER look-ahead bias.** NBER declares recessions 6–18 months after they begin.
  Training on historical USREC labels means the model learned to recognise
  recessions partly from coincident and lagging data. In real-time, it may be
  optimistic until a recession is well underway. The new LEI features (Sahm,
  initial claims) partially mitigate this.
- **Extended training history (2026-05-22).** Training data now pulled directly from
  FRED at monthly frequency back to 1960 (795 rows, 95 recession months = 11.9%).
  This gives 7 recessions (1960, 1969, 1973, 1980, 1990, 2001, 2008, 2020) instead
  of just COVID. Walk-forward CV now runs meaningfully: mean AUPRC=0.57, AUROC=0.71.
  LEI features (Sahm, PERMIT, ICSA) are NaN-filled for 1960–2000 rows; model handles
  this via `fillna(0)` in `load_data_extended()`.
- **Sahm rule threshold.** The real-time Sahm indicator triggers at 0.50 (3-month
  average unemployment rise of ≥0.50pp from 12-month low). Including it as a raw
  feature rather than a binary trigger is intentional — it lets LightGBM learn its
  own threshold, but also means the model may not fire decisively at the classical
  threshold.

## 6. CAPE Quantile Regressor

**File:** `ml/cape_signal.py`  
**Artifact:** `models/cape_signal.pkl`  
**DB table:** `cape_forecasts`  
**Retrain:** `python ml/cape_signal.py train`

### Purpose

Estimates the distribution of 10-year forward real returns conditional on the
current CAPE and real interest rate. Based on Campbell & Shiller (1988, 1998):
CAPE explains ~40% of the variance of 10-year real returns. Used by the decision
engine projection model as the long-horizon valuation signal.

### Inputs

| Feature | Description |
|---------|-------------|
| `log_cape` | Natural log of Shiller CAPE (PE10) — linearises the relationship |
| `real_long_rate` | 10-year nominal yield minus 12-month CPI change |

Training data: Shiller monthly, 1871–2016 (10-year forward returns only available
up to ~2016). All 1,731 rows used for training.

### Method

**Quantile regression** (sklearn `QuantileRegressor`) at q=0.10, 0.50, 0.90 with
L1 regularisation (α=0.01). Three separate models, one per quantile.

Quantile regression minimises the pinball loss (same as the FX model), making no
parametric assumption about the distribution of returns. It directly estimates
the 10th, 50th, and 90th percentile of the conditional return distribution given
today's CAPE and real rate.

**Target:** annualised real total return over the next 10 years, computed from
Shiller's inflation-adjusted price series.

After fitting, predictions are generated for all Shiller rows including post-2016
(where the target is unknown) — this is valid because the model uses only the
features (CAPE, real rate) which are available for all dates.

### Output

`cape_forecasts` — monthly forecasts:

| Column | Description |
|--------|-------------|
| `cape` | Current CAPE (PE10) |
| `ret_q10` | 10th percentile 10Y real return (e.g. −0.07 = −7%/yr) |
| `ret_q50` | Median 10Y real return |
| `ret_q90` | 90th percentile 10Y real return |

### Valuation context (derived, shown alongside)

Not a separate model — computed in `backend/routers/signals.py::_compute_valuation()`:

| Metric | Formula | Meaning |
|--------|---------|---------|
| `trailing_pe` | `SP500 / Earnings` (Shiller latest row) | Current P/E without 10Y smoothing |
| `us_cape` | `PE10` (Shiller) | CAPE for US market (S&P 500 / Shiller) |
| `eps_growth_5y` | `(EPS_now / EPS_5y_ago)^(1/5) − 1` | 5-year EPS CAGR |
| `eps_growth_hist_median` | Median 5Y CAGR since 1950 | Historical benchmark |

**Note (2026-05-22):** `global_cape` (60% US + 40% ex-US estimate) was removed. The
dashboard and signals endpoint now show only `us_cape`. All ML models (HMM, CAPE
regressor) use Shiller S&P 500 data — consistent to use the same US-only metric throughout.

### Known Limitations

- **US-only.** Shiller data is S&P 500. VWCE is ~60% US, ~40% rest of world.
  The `global_cape` correction was removed (2026-05-22) — US CAPE is now the
  displayed metric, consistent with HMM and CAPE model data sources.
- **CAPE=39 is ~90th historical percentile.** The model is extrapolating slightly
  outside the densest training region.
- **No earnings growth adjustment.** CAPE assumes long-run mean reversion of earnings.
  If AI/technology has structurally raised margins and earnings growth, historical
  CAPE–return relationships may overstate risk. The `eps_growth_5y` metric displayed
  alongside CAPE provides manual context for this.
- **10-year horizon only.** Returns at 1–3 year horizons are not well-predicted by
  CAPE; momentum and macro signals dominate at short horizons.

## 7. PCA Diversification Index

**File:** `ml/correlation_pca.py`  
**Artifact:** none (computed from DB)  
**DB tables:** `correlation_stats`, `diversification_index`  
**Recompute:** `python ml/correlation_pca.py compute`

### Purpose

Measures how independently the assets in a portfolio move. Complementary to the
regime signal: in risk-off episodes, all assets correlate and diversification
collapses. The diversification index shows whether the current market structure
is providing genuine risk reduction.

### Inputs

5 daily return series from `daily_features`:

| Series | Asset class |
|--------|-------------|
| `acwi_ret_1d` | Global equities |
| `gold_ret_1d` | Gold (safe haven) |
| `tlt_ret_1d` | US long bonds (safe haven) |
| `usdpln_ret_21d` | PLN/USD rate (currency risk) |
| `vix_change_5d` | VIX momentum (fear gauge) |

Rolling window: 63 trading days (~3 months).

### Method

**Principal Component Analysis** on the rolling correlation matrix — mathematically
identical to **Empirical Orthogonal Function (EOF) analysis** in atmospheric science.

Steps:
1. Compute the 5×5 rolling correlation matrix over the last 63 days.
2. Run PCA (standardised — PCA on the correlation matrix, not covariance).
3. Record `pc1_explained` = fraction of total variance explained by the first
   principal component.
4. **Diversification index = 1 − pc1_explained.**

Interpretation:
- `div_index = 0.60` → 40% of variance is driven by one common factor (the "market
  beta" mode). The remaining 60% is idiosyncratic — assets are moving independently.
  This is the current value (2026-05-16).
- In a risk-off crisis, all assets correlate → PC1 explains 80–90% → `div_index ≈ 0.10`.

The top 3 pairwise correlations from PAIR_MAP are also stored for display:
ACWI-GOLD, ACWI-BONDS, ACWI-USD.

### Output

`diversification_index` — daily snapshot:

| Column | Description |
|--------|-------------|
| `div_index` | 1 − PC1 explained variance (0–1, higher = more diversified) |
| `pc1_explained` | Fraction of variance in the first PC |
| `regime` | Current HMM state label at that date |

`correlation_stats` — per-pair rolling correlations.

### Known Limitations

- **Only 5 assets.** The correlation structure of a real VWCE portfolio includes
  hundreds of underlying stocks. These 5 represent asset-class proxies only.
- **63-day window.** Shorter windows are noisier; longer windows miss regime shifts.
  63 days is a standard choice but somewhat arbitrary.
- **VIX and USD/PLN are not portfolio assets.** They are included as fear-gauge
  and currency-risk proxies. Their inclusion in PCA inflates the measured
  diversification because they naturally move differently from equities.

## 8. Decision Engine (rule-based, uses all models above)

**File:** `backend/routers/decision.py`  
**No artifact** — computed at request time from DB outputs of models 1–6.

### Logic

```
WAIT  if (hmm.prob_bear > 0.50 AND recession_prob > 0.40)
         OR spread_10y_3m < −0.50   (deep yield curve inversion)

DCA   if hmm.state == 'stagflation'   (expensive, low expected return)
         OR hmm.prob_bear > 0.35
         OR recession_prob > 0.30
         OR vol_21d > 0.25            (annualised vol > 25%)

INVEST otherwise
```

### Projection model (10-year return estimate)

Three signals blended with horizon-dependent weights:

```python
w_momentum(T)  = max(0, 1 − T/3) × 0.40     # dominates 1–3Y
w_cape(T)      = 0.55 × exp(−0.5 × ((T−5)/3)²)   # peaks at 5Y
w_base_rate(T) = 1 − w_momentum(T) − w_cape(T)    # dominates 10Y+
```

- **Momentum** (1–3Y): recent ACWI return, dampened if CAPE > 20.
- **CAPE** (3–7Y): Shiller E/P minus risk-free rate (60%) + Asness decile table (40%).
- **Base rate** (7–10Y+): historical equity risk premium, ~5%/yr real.

References: Jegadeesh-Titman (1993) for momentum, Campbell-Shiller (1988) for CAPE
predictability, DMS (2025) for long-run equity premium.

## Retraining Checklist

When retraining any model:

1. **Run pipeline first** to refresh `daily_features` with latest data:
   `python ingestion/pipeline.py`
2. **Retrain** the model: see "Retrain" command in each section above.
3. **Upload artifact to GCS:**
   `gsutil cp models/<artifact>.pkl gs://investor-intelligence-496113-backup/models/<artifact>.pkl`
4. **Push to main** to trigger Cloud Build deployment (Cloud Build pulls models from GCS).
5. **Verify** on the live endpoint (`/signals`, `/dashboard`, `/decision`).

The HMM model also requires running:
`python ml/regime_duration.py compute`
after retraining, because the KM survival table depends on the HMM state history.
